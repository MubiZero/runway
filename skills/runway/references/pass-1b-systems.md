# Проход 1b: системные классы дефектов

Дополняет [pass-1-defects.md](pass-1-defects.md). Те двенадцать классов про поведение клиента
при отказах. Эти восемь про то, на чём проекты ломаются **на пилоте**: данные, связь,
железо, установка, безопасность, эксплуатация. Для каждого: **признак** (как искать),
**цена** (что это для человека), **лечение**, **закрепление** (какой тест или проверка).

Выбирай классы, правдоподобные для части. У проекта без базы нет класса «данные», у
проекта без установки нет класса «обновление».

---

## 1. Данные: целостность и миграции

**Признак.** Запись в несколько шагов без транзакции. Схема меняется без миграции или с
необратимой миграцией. Нет ограничений в базе, всё держится на коде. Обновление
приложения может открыть старую базу новым кодом. Нет бэкапа или бэкап ни разу не
восстанавливали.

**Цена.** Половина записи после сбоя. Потерянные данные клиента после обновления.
Невозможность откатиться.

**Лечение.** Транзакции на многошаговые записи. Ограничения (уникальность, внешние ключи,
проверки) на уровне базы. Версионированные миграции, прогнанные на копии боевых данных. Откат
для каждой миграции или явная запись, что он невозможен и почему. Восстановление из
бэкапа проверено на чистой машине.

**Закрепление.** Тест миграции вверх на копии «грязных» данных. Тест сбоя посреди записи:
после него состояние либо целиком старое, либо целиком новое.

## 2. Офлайн, синхронизация, гонки

**Признак.** Приложение предполагает, что связь есть. Нет очереди действий на время обрыва.
Два клиента меняют одно и то же без правила побеждающего. Операция идёт «проверить, потом
записать» без блокировки или условной записи. Время сравнивается по часам клиента.

**Цена.** Потерянные действия при обрыве. Тихая перезапись чужих изменений. Дубли и
расхождение остатков, касс, статусов.

**Лечение.** Очередь исходящих действий с повтором и ключом идемпотентности. Явное правило
конфликтов (последняя запись, слияние по полям, отказ с объяснением) и оно записано в коде.
Условная запись (версия, ETag) вместо «прочитал и записал». Время для порядка берётся с
сервера или из логических счётчиков. Индикатор «нет связи, действия ждут» и понятный итог
после восстановления.

**Закрепление.** Тест: выключили сеть посреди операции, включили, итог один и без дублей.
Тест: два клиента правят одно, видимый и ожидаемый результат.

## 3. Бюджеты ресурсов

**Признак.** Нет измеренных цифр: память после старта и через час, CPU в простое, время
холодного старта, число и размер запросов на старте, размер дистрибутива. Утечки
(подписки, таймеры, слушатели без отписки). Опрос сервера по таймеру вместо push или
долгого соединения. Крупные ресурсы грузятся целиком и сразу.

**Цена.** На слабых машинах приложение тормозит или падает, трафик съедает дорогой
интернет, обновления тянутся часами.

**Лечение.** Записать бюджеты в `RELEASE.md` (из среды пилота). Замерить на целевой среде.
Лениво загружать, кэшировать, сжимать, делать запросы пачками, заменить опрос на
событийный обмен, где можно. Утечки закрывать корнем: общий хук или сервис с
отпиской, не десять правок.

**Закрепление.** Замер как проверка в gate: «старт ≤ N с, память после часа ≤ M МБ».
Сторожевой тест на размер пакета, если проект его собирает.

## 4. Установка, обновление, откат

**Признак.** Установка требует ручных шагов, не описанных нигде. Нет проверки
зависимостей среды (рантайм, права). Обновление перезаписывает файлы без проверки
целостности и без возможности вернуть. Обновление скачивается заново на каждую машину.
Нет версии в интерфейсе, по которой поддержка поймёт, что стоит у клиента. Нет
тихого обновления либо оно возможно без согласия на критическую версию.

**Цена.** Клиент не может поставить сам. Неудачное обновление выводит из строя точку без
способа вернуться. Скачивание того же обновления десять раз по дорогому каналу.

**Лечение.** Установщик с проверкой среды и понятным сообщением о причине отказа.
Обновление: проверка подписи или хэша, атомарная замена, сохранение прошлой версии для
отката, дельта-обновление, если артефакты большие. Для парка машин в одной локальной сети
одна загрузка и раздача внутри сети. Автообновление по расписанию вне рабочих часов.
Версия видна в интерфейсе и в логах. Сценарий аварийного отката описан и проверен.

**Закрепление.** Проверка в gate G1/G2: установка с нуля и обновление с предыдущей
версии на чистой машине, включая откат.

## 5. Безопасность

**Признак.** Права проверяются только в интерфейсе (кнопка скрыта, а запрос проходит).
Идентификаторы в запросах не проверяются на принадлежность пользователю (можно подставить
чужой). Вход без ограничения попыток. Токены в `localStorage` без причины, долгоживущие,
без отзыва. Секреты в репозитории или в клиентском пакете. SQL или команды собираются
конкатенацией. Загрузка файлов без проверки типа и размера. Отладочные ручки в боевой
сборке. Журнал действий без неизменяемости там, где она нужна (деньги, права).

**Цена.** Чужие данные, чужие деньги, захват аккаунта. Для пилота на реальных клиентах это
блокер без обсуждения.

**Лечение.** Проверки прав на сервере для каждой ручки, по принадлежности объекта, не по
скрытой кнопке. Ограничение попыток, блокировка, отзыв токенов. Параметризованные запросы.
Секреты в окружении или хранилище, найденное в истории ротируется. Валидация на границе
доверия. Зависимости без критичных уязвимостей. Не ослабляй проверку ради зелёного (R5).

**Закрепление.** Тест на доступ вне интерфейса: запрос от пользователя A к объекту
пользователя B возвращает отказ. Проверка «секретов нет» в CI или в gate.

## 6. Наблюдаемость

**Признак.** Ошибки глотаются или пишутся только в консоль. Нет краш-репортов от клиентов.
Нет идентификатора запроса, по которому связать клиент и сервер. Логи без уровня и
контекста или с персональными данными. Тот, кто поддерживает пилот, не может ответить
на вопрос «что случилось на машине клиента вчера вечером».

**Цена.** Любой сбой пилота превращается в гадание по рассказу пользователя. Пилот
останавливают не из-за самой ошибки, а из-за невозможности её понять.

**Лечение.** Структурные логи с уровнем и идентификатором корреляции. Централизованный
сбор ошибок и краш-репортов с согласием и без персональных данных. Диагностический
пакет, который клиент отправляет одной кнопкой. Заметные состояния «связь потеряна»,
«синхронизация ждёт» в интерфейсе.

**Закрепление.** Проверка G10: вызвать ошибку и найти её след так, как это будет делать
поддержка.

## 7. Зависимости и цепочка поставки

**Признак.** Версии не закреплены. Нет lock-файла в репозитории. Зависимость заброшена
или единственный мейнтейнер пропал. Транзитивные уязвимости. Пакет подтягивается из
неподписанного источника при сборке. Пакет для одной функции на пять строк.

**Цена.** Невоспроизводимая сборка, уязвимости, поломка от чужого релиза за день до пилота.

**Лечение.** Lock-файл в репозитории. Аудит зависимостей в CI. Убрать пакеты, которые
заменяются несколькими строками или стандартной библиотекой. Для критичных зависимостей
записать причину выбора и план замены.

**Закрепление.** Сборка с нуля по lock-файлу воспроизводима. Аудит зависимостей входит в
gate G8.

## 8. Конфигурация и окружения

**Признак.** Адреса, ключи и флаги зашиты в код. Отличия между окружениями живут в
головах. Настройки меняются правкой файла на машине клиента. Нет значений по
умолчанию, приложение падает, если параметра нет.

**Цена.** Разовое «у меня работает» вместо воспроизводимой установки. Опасность запустить
пилот против боевой базы разработчика или наоборот.

**Лечение.** Одна точка чтения конфигурации, проверка при старте с понятным сообщением,
значения по умолчанию для безопасных параметров, раздельные профили окружений,
запрет секретов в репозитории. Конфигурация клиента меняется через интерфейс или
центральную настройку, не через правку файлов.

**Закрепление.** Тест старта без обязательного параметра: понятная ошибка, а не падение.
