# Pass 1: Client & Transport Defect Classes (12 Classes)

Question: **Does the code behave properly when things go wrong?** Always fix the entire defect class in the shared layer (transport, hooks, UI kit, i18n catalog) and lock it with a guard test explaining *why*.

1. **Unbounded Request Timeout:** No `timeout`/`AbortSignal.timeout`/`CancellationToken` in the HTTP client (or timeout applied *after* `await`). *Cost:* Dropped Wi-Fi/mobile TCP connections hang on "Saving…" forever. *Fix:* Enforce a 10–30 s transport timeout; propagate caller cancellation separately from server timeout.
2. **Retry Creates a Duplicate:** Idempotency key generated inside the send function per call (`randomUUID()`) instead of per user attempt. *Cost:* Lost response + second tap charges/creates twice. *Fix:* Tie the idempotency key to the attempt + payload hash; reset only on success or payload edit.
3. **Transient Refresh Failure Logs the User Out:** `if (!res.ok) clearSession()` on token refresh. *Cost:* A 502/503 or brief disconnect kicks the user to login mid-operation. *Fix:* Clear session only on explicit `401`/`403` token rejection; validate refresh payload shape.
4. **Generic Error Hiding the Cause:** Showing "Failed to load data" when the server returned a specific error code (`403`, `409`, `429`). *Fix:* Centralize error parsing by server error code and surface the specific reason + context title.
5. **Silent Failure:** Empty `catch {}` or `.catch(() => setState([]))` turning network errors into fake empty states, `"—"` placeholders, or dead buttons. *Fix:* Model distinct states (`unrequested/no-permission` ≠ `loading` ≠ `empty` ≠ `error` with retry).
6. **Dead-End Error Without Recovery:** Error state with no Retry button (or full-screen error replacing live POS/money state on a partial background failure). *Fix:* Always provide an in-place Retry; show partial failures as a non-destructive banner over existing data.
7. **Double-Tap / Unblocked Mutation:** Mutating button/menu item/row action lacks `disabled` / `if (pending) return` during in-flight requests (or lacks `:disabled` visual styling). *Fix:* Single busy state disabling both click and visual hover/active styles.
8. **Raw Server Enums in UI:** Rendering `{record.outcome}`, `{entry.kind}`, or `{status}` without i18n mapping. *Fix:* Map known enum codes through the localization catalog; fall back gracefully for unknown future codes.
9. **Unbounded Data Scale:** `ToListAsync()` / `SELECT *` without pagination, N+1 query loops, or in-memory grouping/counting of entire tables. *Fix:* Push `GROUP BY`/`COUNT`/`SUM` and cursor pagination into SQL; test against real PostgreSQL, not in-memory mocks.
10. **Permission & Half-Access Asymmetry:** Route/tab visible to a restricted role while its API returns `403`, or "No debts" rendered when the balance query wasn't permitted. *Fix:* Unify route guards and render an explicit "Insufficient permissions" state instead of fake zeros.
11. **Bypassing Shared i18n & Formatters:** Hardcoded strings next to a live i18n catalog, custom date/money formatters, or manual string pluralization without ICU MessageFormat. *Fix:* Route all strings and formats through the shared catalog and add catalog parity/dead-key guard tests.
12. **Swallowed Server Detail:** API response already includes `deviceName`, `remainingAttempts`, or `duration`, but the UI prints a vague "Busy" or "Invalid code". *Fix:* Surface the specific field already present in the payload.
