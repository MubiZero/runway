# runway

> A Claude Code skill that takes an **existing codebase** from "almost done" to a real pilot.
> It analyses the code first, interviews you one question at a time (every question comes with
> options and a recommended answer), writes the agreements into `docs/release/`, and then works
> autonomously down a priority queue until the release gate is green.

Проекты застревают на пути к релизу не из-за кода, а из-за трёх пустот: нет определения
«готово», нет порядка работ, нет памяти между сессиями. `runway` закрывает все три и после
короткого интервью работает сам.

## Как это работает

| # | Фаза | Что происходит |
|---|---|---|
| 1 | **Анализ** | Read-only разбор кода и состояния: стек, история git, базовая линия (сборка, тесты), запуск, карта функций, зависимости, безопасность, данные, готовность к выпуску. Итог: `ANALYSIS.md` с вердиктом «насколько далеко до пилота», всё с доказательствами |
| 2 | **Интервью** | Вопрос за вопросом, 2–4 варианта, рекомендация первой, предзаполнено фактами из анализа. «ок» принимает рекомендацию, «остальное по умолчанию» принимает все оставшиеся |
| 3 | **Контракты** | `RELEASE.md` (цель, срок, gate), `PROFILE.md` (среда, автономия, агенты), `STATE.md` (очередь, решения, вопросы) |
| 4 | **Карта и очередь** | Роль × экран × сценарий, приоритеты P0–P3 |
| 5 | **Цикл** | По частям: три прохода (дефекты, трение, дизайн), симуляция ролей агентами на запущенной сборке, связки между частями, один класс = один PR |
| 6 | **Gate** | Проверяемые критерии, чек-лист пилота, честный отчёт |

Единственная остановка перед автономной работой: вы читаете `RELEASE.md` и таблицу границ
автономии и говорите «поехали». Деплой, миграции боевых данных, удаление и платежи всегда
только по вашей явной команде.

## Что внутри

```
.claude-plugin/                 манифесты плагина и маркетплейса
skills/runway/
  SKILL.md                      шесть фаз, режимы входа, границы автономии, форма отчёта
  references/
    analysis.md                 фаза 1: 13 областей анализа и формат ANALYSIS.md
    interview.md                фаза 2: правила и 9 вопросов с вариантами
    loop.md                     фаза 5: алгоритм итерации, связки, агенты, остановка
    personas.md                 симуляция ролей на запущенной сборке
    tech-choices.md             выбор и смена технологий по доказательствам, шаблон ADR
    gate.md                     критерии релиза и чек-лист пилота
    pass-1-defects.md           12 классов дефектов клиента и транспорта
    pass-1b-systems.md          8 системных классов: данные, офлайн, ресурсы, установка, безопасность…
    pass-2-friction.md          трение в сценариях
    pass-3-design.md            дизайн и восприятие
    working-method.md           разведка, делегирование, форма PR, слияние
    honesty.md                  правила честности
  templates/                    RELEASE.md, PROFILE.md, STATE.md
  evals/evals.json              сценарии проверки скилла
```

`SKILL.md` работает как оглавление: подробности загружаются, только когда нужны.

## Установка

```
/plugin marketplace add MubiZero/runway
```

```
/plugin install runway@runway
```

Или вручную, скопировав **содержимое** `skills/runway/` в `~/.claude/skills/runway/`.

## Использование

Откройте Claude Code в корне проекта и скажите, например:

- «доведи проект до релиза»
- «мы слишком долго не выходим в релиз, подготовь к пилоту»
- «оцени состояние проекта и составь план»
- «продолжай по STATE.md» (возобновление в новой сессии)

## Происхождение

Три прохода (дефекты, трение, дизайн) и правила честности выросли из
[three-pass-audit](https://github.com/MubiZero/three-pass-audit). `runway` берёт их как фазу 5 и
добавляет вокруг анализ, интервью, контракты, очередь, симуляцию ролей и gate.
