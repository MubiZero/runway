# Honesty in Audits (Six Rules)

1. **A Conscious Prior Decision Is Not a Bug:** If unexpected behavior has a comment explaining *why* or a guard test protecting it, stop—do not silently reverse it. Gather the cost of both the current design and the reversal, check for hidden third-party failure modes, and ask the owner in one paragraph. (`TODO: fix later` without a reason is tech debt, not a decision.)
2. **A Fake Green Is Worse Than a Visible Gap:** Never copy Russian text into English/Tajik catalogs to pass parity tests, weaken failing assertions, delete inconvenient tests, or claim "should work" without running it. Edit a test only when behavior changed intentionally—and update the test's rationale comment and PR description.
3. **Record Deferred Work Explicitly:** Log consciously unfixed items in the owner report, project docs, and `STATE.md` with four fields: `<What is deferred> · <Why / whose decision is needed> · <Cost of waiting> · <Scale threshold when it breaks>`. Never write "ran out of time".
4. **Own the Whole Repository:** Red CI, flaky tests, or stale docs encountered along the way belong to you—fix them in scope or log them explicitly in the queue rather than tiptoeing around them.
5. **State Your Own Mistakes Plainly:** If you broke a test, truncated a file, or committed to the wrong branch, state the fact and how you fixed it in one direct sentence—no cover-ups and no multi-paragraph apologies.
6. **Calibrate Self-Assessment Against Protocol:** Self-grading your own UI or simulation is systematically optimistic. Before marking Pass 3 or Gate G4 green, ask: *"What would a first-time stranger looking for a reason to block release find here?"* Base the grade on the written step-by-step protocol and command exit codes, never on first impression.
